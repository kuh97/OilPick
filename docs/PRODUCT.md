## 1. Product Overview

### 1.1 한 줄 정의

출발지와 목적지를 입력하면 그 경로에서 주유하기 가장 좋은 주유소를 찾아주는 서비스.
**단, 경로 위에 없으면 "없습니다"로 끝내지 않고, 우회할 가치가 있는 주유소까지 찾아 경로를 만들어준다.**

### 1.2 해결하려는 문제

기존 서비스(티맵·네이버지도·카카오내비·오일나우)는 전부 **반경 하드 필터**를 씁니다.

```
경로 확정 → 반경 N km 안에서 검색 → 조건에 맞는 게 없음 → "검색 결과 없음"
                                                        ↑
                                            사용자의 탐색이 여기서 끝난다
```

반경 밖 주유소는 **존재 자체가 사용자에게 전달되지 않습니다.** 사용자는 "조금만 돌아가면 되는 곳이 있을 텐데"를 확인할 방법이 없습니다.

### 1.3 핵심 가치

> **반경으로 자르지 않는다. 우회 비용과 이득을 비교해서 순위를 매긴다.**

이 제품의 차별점은 두 줄뿐입니다.

1. 반경 밖까지 탐색한다
2. 우회 비용과 이득을 계산해서 순위를 매긴다

나머지 기능은 전부 이 둘을 성립시키기 위한 부속입니다.

### 1.4 이 차이가 드러나는 상황

정직하게: **휘발유·경유로 짧은 경로를 검색하면 기존 서비스와 차이가 거의 없습니다.** 전국에 주유소가 1만 개 이상이라 경로 주변에 항상 있기 때문입니다.

차이가 드러나는 상황은 셋입니다.

| 상황                                         | 왜 발생하는가                              |
| -------------------------------------------- | ------------------------------------------ |
| **LPG 차량**                                 | 자동차충전소는 주유소보다 훨씬 희소함      |
| **조건 조합** (예: LPG + 세차)               | 두 조건을 모두 만족하는 곳은 급격히 줄어듦 |
| **저밀도 구간** (강원 산간, 고속도로 장구간) | 지역 자체에 시설이 적음                    |

→ 제품 메시지와 초기 사용자 확보를 **LPG·장거리**에 맞춥니다.

### 1.5 타깃 사용자

| 우선순위 | 세그먼트                            | 필요한 이유                                  |
| -------- | ----------------------------------- | -------------------------------------------- |
| **1**    | LPG 차량 장거리 운전자              | 충전소 밀도가 낮아 "경로에 없음"이 자주 발생 |
| 2        | 조건이 있는 운전자 (주유 + 세차 등) | 조건 조합 시 후보가 급감                     |
| 3        | 주말 장거리 레저 운전자             | 우회 비용 판단 니즈. 후보 부족은 잘 안 생김  |
| 4        | 영업·출장 운전자                    | 주행거리가 커서 절감액 절대치가 큼           |

**타깃하지 않음**

- 일상 근거리 주행자 — 단골 주유소가 있고 경로 최적화 여지가 없음
- 전기차 운전자 — 체류 시간·판단 변수·데이터 신선도 요구가 전부 다름. **별도 제품** (§2.3)

### 1.6 설계 원칙 5가지

개발 중 판단이 갈릴 때 이 순서로 결정합니다.

1. **계산은 전부 결정론적으로.** 금액·거리·시간에 AI를 쓰지 않습니다.
2. **추정치와 실측치를 구분해서 표시한다.** `d_perp` 기반 추정은 `약 4.2km`처럼 "약"을 붙입니다. 검색은 Valhalla 경로 실측을 내부 계산에 사용하지만, Kakao 최종 확인 전까지 확정 수치로 표시하지 않습니다.
3. **모르는 값은 묻지 않고 기본값을 쓰되, 기본값을 화면에 밝힌다.** 연비를 물으면 이탈합니다.
4. **탐색을 넓혔으면 넓혔다고 말한다.** 이 고지가 곧 제품의 정체성입니다.
5. **빈 화면으로 끝내지 않는다.** 반드시 대안(조건 완화·목적지 근처 검색)을 제시합니다.

| 광고·수익화                  | 오피넷 상업적 이용은 한국석유공사 사전 협의 필요 |

### 2.3 향후 확장 (범위 밖, 명시만)

- **차종·연료·연비·하이패스 등 세부 차량 정보 입력** — 지금은 승용차 기준 기본값만 사용(§9.2). 개인화하려면 로그인으로 저장해야 하는데, 로그인 자체가 MVP에서 제외된 상태(§2.2)라 로그인 인프라가 생긴 뒤 별도 Phase로 진행
- **다구간 주유 최적화** — 장거리에서 여러 번 주유할 때 "어디서 얼마씩". 연료 잔량 입력 정확도 문제로 난이도 높음
- 사용자 가격·폐업 제보
- 주행 중 실시간 추천 (앱 전용)
- 전기차 충전소 — **별도 제품.** 아래 이유로 이 제품에 합치지 않습니다

| 축                 | 내연기관 | 전기차                      |
| ------------------ | -------- | --------------------------- |
| 체류 시간          | 5분      | 급속 30~60분                |
| 판단 변수          | **가격** | **충전기 가용성·규격·출력** |
| 데이터 신선도 요구 | 하루 6회 | **분 단위 실시간**          |
| 실패의 대가        | 불편     | 주행 불가                   |

"+18분 우회"와 "충전 45분"이 섞이면 §8의 목적함수가 성립하지 않습니다.
다만 DB 스키마는 일반 개념(`refuel_point` / `energy_type`)으로 두어 향후 마이그레이션을 피합니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §7).

## 3. 핵심 용어

개발 전체에서 이 용어를 그대로 씁니다. **단위는 미터(m) · 초(s) · 원(₩)입니다** ([`../AGENTS.md`](../AGENTS.md) §7.4).

| 용어             | 기호                  | 정의                                                                  |
| ---------------- | --------------------- | --------------------------------------------------------------------- |
| 기본 경로        | `R₀ᵖ`                 | 우선순위 p(`RECOMMEND`·`TIME`·`DISTANCE`)의 출발지 → 목적지 직행 경로 |
| 기본 거리 / 시간 | `D_baseᵖ` / `T_baseᵖ` | 후보를 발견한 기본 경로 p의 총 거리(m) / 총 소요시간(초)              |
| 경유 경로        | `R_sᵖ`                | 기본 경로 p를 기준으로 주유소 s를 경유한 출발지 → 목적지 경로         |
| **우회 거리**    | `ΔD(s,p)`              | `R_sᵖ.distance − D_baseᵖ` (m, 음수면 0)                               |
| **우회 시간**    | `ΔT(s,p)`              | `R_sᵖ.duration − T_baseᵖ` (초, 음수면 0)                              |
| 수직 거리        | `d_perp(s,p)`         | 주유소 s에서 기본 경로 p 폴리라인까지의 최단 직선거리 (m)             |
| 탐색 범위        | `T1/T2/T3`            | `d_perp` 기반의 기준가 표본·회랑 범위 개념 (§6.4)                     |
| 기준가           | `P_ref`               | "그냥 아무 데나 들렀을 때 낼 법한 가격" (§6.3)                        |
| **순절감액**     | `NetSaving(s)`        | 기준가 대비 절약분에서 우회 연료비를 뺀 금액 (§6.5)                   |
| 여정 총비용      | `TotalCost(s)`        | 주유비 + 우회 연료비                                                  |
| 기준 모드        | —                     | 최단거리 / 최소비용 / 균형 (§8)                                       |

> 이하 계산식에서 후보가 연결된 기본 경로의 우선순위 `p`는 문맥상 생략할 수 있습니다. 예를 들어
> `ΔD(s)`는 실제로 `ΔD(s,p)`를 뜻합니다.

## 4. User Flow

### 4.1 화면 구조

```
[홈 / 경로 입력]
      │
      ├──▶ [결과 목록] ──▶ [주유소 상세] ──▶ 외부 내비 앱
      │         │
      │         └──▶ [필터 시트]
      │
      └──▶ [내 주변 주유소] ──▶ 외부 내비 앱
```

라우팅: `/`, `/result`, `/station/:id`, `/nearby`. 필터는 모달.

### 4.2 핵심 시나리오 — LPG 장거리

```
1. 홈에서 "성남" → "춘천" 입력, 연료 LPG 선택
2. [찾기] 탭 → 우회 거리 `없음`으로 경로상 후보 확인
3. 결과 화면에서 허용 우회 거리 15km 선택
4. 로딩: 경로 찾는 중 → 주유소 찾는 중 → 범위를 넓히는 중 (선택 거리+3km, 최대 15km) → 우회 경로 계산 중
5. 결과: "경로에서 7km 떨어진 곳까지 살펴, 우회 가능한 충전소도 함께 보여드려요"
6. 1위 카드: 🟡 우회 · E1 홍천충전소 · 1,102원/L · +18분 · +12.4km · 💡 3,252원 이득
7. 카드 탭 → 상세에서 기본 경로(회색)와 경유 경로(강조)를 지도로 비교, 추천 이유 확인
8. [카카오맵] 탭 → 주유소가 경유지로 들어간 경로가 카카오맵에서 열림
```

**5단계의 고지 배너가 이 제품의 존재 이유입니다.** 경로 밖의 후보도 실제 우회 비용을 계산해 함께 보여주는 순간입니다.

> 4단계의 `15km`는 **탐색 상한**(`T3_MAX`)이고, 5단계의 `7km`는 **실제로 채택된 후보의 최대 거리**입니다. 둘은 다른 값이며 섞어 쓰면 안 됩니다 (§5.3 ②, §10.3).

### 4.3 보조 시나리오

| 시나리오           | 흐름                                                      |
| ------------------ | --------------------------------------------------------- |
| 경로상에 후보 충분 | 우회 배너 없이 T1·T2 위주 결과. 기존 서비스와 유사한 경험 |
| 필터로 0건         | 활성 필터가 원인일 수 있음을 안내 → 초기화 버튼 제시       |
| 전 구간 0건        | 목적지 근처 / 출발지 근처 주유소 보기 제시                |
| 경로 없이 주유     | 홈에서 [내 주변 주유소] → 가격순/거리순                   |

## 5. Feature Specification

### 5.1 F1 — 경로 입력

**목적** 출발지·목적지를 좌표로 확정한다.

**입력**

| 항목                         | 필수 | 방식                                              |
| ---------------------------- | ---- | ------------------------------------------------- |
| 출발지                       | ✅   | 장소 검색 자동완성 / "현재 위치" 버튼             |
| 목적지                       | ✅   | 장소 검색 자동완성                                |
| 연료 종류                    | ✅   | 3택 (휘발유 / 경유 / LPG). 기본값은 마지막 선택값 |
| 고속도로·자동차전용도로 회피 | ➖   | 체크박스(스위치). 기본값 OFF, `localStorage` 저장 |

**처리 규칙**

- 검색어 `PLACE_QUERY_MIN_LEN`(2자) 이상부터 자동완성 호출, `PLACE_DEBOUNCE_MS`(300ms) 디바운스
- 자동완성 결과 최대 5건. `장소명 + 주소` 2줄 표시
- "현재 위치"는 브라우저 Geolocation. 권한 거부 시 **조용히 무시**하고 텍스트 입력으로 유도
- 현재 위치가 선택되면 좌표를 역지오코딩해 도로명 주소(없으면 지번 주소)를 출발지 이름으로 표시하고, 주소 조회 실패 시에만 `현재 위치`로 표시한다.
- 출발지와 목적지 사이가 `MIN_OD_GAP`(500m) 이내면 오류 안내
- 최근 검색 3건을 `localStorage`에 저장하고 홈에 노출

**고속도로·자동차전용도로 회피 (Phase 12 추가)**

카카오 길찾기 API의 `avoid=motorway` 그대로다. §5.2의 시설·브랜드 필터나 §5.3 ⑥
최대 우회 거리 필터와 달리 **후보를 거르는 게 아니라 `baseRoute` 자체를 바꾸는 검색
조건**이다 — 체크 상태가 바뀌면 카카오 길찾기부터 다시 호출해야 한다(경로 폴리라인이
통째로 달라지므로 bbox 재계산 → 후보 재수집 → 정밀 재측정까지 파이프라인 전체가
다시 돈다). 그래서 클라이언트에서는 고속도로 회피를 경로 조건으로 다루고, 시설·브랜드 등
표시 필터와 구분한다. `maxDetourDistanceKm`도 DB 후보 범위와 실제 판정을 바꾸는 검색 입력이므로
서버에서는 캐시 키에
반드시 포함한다 — 빠뜨리면 회피를 켠 사용자가 끈 사용자의(또는 그 반대) 캐시된 경로를
그대로 받는다 (`infra/cache/keys.routeKey`).

**체크 해제(기본값)는 모든 도로 조건을 뜻하지 않습니다.** 이 서비스는 같은 `avoid` 조건에서
카카오 `RECOMMEND`·`TIME`·`DISTANCE` 세 기본 경로를 비교합니다. 폴리라인이 같은 응답은 하나로
합치며, 고속도로 회피 여부는 세 요청 모두에 동일하게 적용합니다.

**출력**


### 5.2 F2·F6 — 필터

**목적** 후보 주유소를 사용자 조건으로 좁힌다.

**필터 항목** (오피넷이 제공하는 것만)

| 그룹     | 항목                     | 타입                              | 위치            |
| -------- | ------------------------ | --------------------------------- | --------------- |
| **연료** | 휘발유 / 경유 / LPG      | 단일 선택 · **필수**              | 홈 화면         |
| 우회     | 허용 우회 거리           | 설정 카드 → 바텀시트 단계형 슬라이더 (3·5·10·15km) | 결과 화면, 필터 시트 밖 |
| 시설     | 세차장 / 경정비 / 편의점 | 각각 토글                         | 필터 시트       |
| 브랜드   | 아래 매핑표              | 다중 선택                         | 필터 시트       |
| 품질     | 품질인증 주유소만        | 토글                              | 필터 시트       |
| 셀프     | 셀프 주유소만            | 토글                              | 필터 시트       |

> **"허용 우회 거리"는 표시 필터가 아니라 검색 파라미터입니다 ★**
> 결과 화면에서 필터 시트 밖의 별도 거리 설정 카드를 누르고 적용하면 **재검색**합니다 (AGENTS.md 불변식 8).
> 반대로 시설·브랜드·품질인증·셀프 필터는 필터 시트에서 적용해도 재검색하지 않고, 이미 받은
> 후보 목록만 클라이언트에서 다시 걸러서 보여줍니다.
>
> **허용 우회 거리는 경로상 후보 수와 무관하게 항상 표시됩니다.** 경로상 후보가 있으면 기본값
> `없음`에서 경로상 후보만 보여주고, 거리를 선택하면 기존 경로상 후보를 유지한 채 우회 후보를
> 추가 탐색해 하나의 목록으로 합칩니다. 경로상 후보가 없으면 기존 기본값 5km로 자동 확장합니다.
> 브랜드·시설 필터를 바꿔도 이미 받은 목록만 다시 계산합니다.
>
> **경로상 후보가 있으면 거리 선택지는 없음·3·5·10·15km이고 기본값은 없음입니다.** 경로상
> 후보가 없으면 5km가 자동 적용되고 `없음`은 제공하지 않습니다. 서버는 선택 또는 자동 적용된
> 거리+3km를 DB 검색 반경으로 사용하고, 최대 `T3_MAX`(15km)를 넘기지 않습니다. 실제 후보
> 통과 여부는 Valhalla의 `ΔD`로 확인합니다.
>
> **이 값은 현재 경로에만 적용합니다.** 사용자가 10km로 바꿔 재검색한 뒤 출발지나 목적지를
> 새로 입력하면 사용자가 고른 허용 우회 거리는 초기화됩니다. 새 경로에 경로상 후보가 있으면
> `없음`, 없으면 자동 5km가 적용됩니다. 이전 경로의 검색 조건을 새 경로에 이어 붙이지 않습니다.

> **셀프 필터는 유가 CSV 전환(docs/MIGRATION-DB.md §1.1·§9.4)으로 추가됐습니다.** 오피넷
> 실시간 API엔 없지만 "과거 판매가격" CSV의 `셀프여부` 컬럼이 전 주유소에 채워져 있어
> `refuel_point.is_self`로 적재합니다. 셀프여부 미상(상세 API로만 채워진 소수 행)은
> "셀프만" 필터에서 제외합니다.

**브랜드 코드 ↔ 표시명 매핑** — 오피넷 `POLL_DIV_CD`

**제공하지 않는 필터**

| 항목                   | 이유                                                |
| ---------------------- | --------------------------------------------------- |

| 타이어 공기압 / 화장실 | 공개 데이터 없음                                    |

> 없는 이유를 밝히면 "왜 없지?"가 "아 그렇구나"가 됩니다.

**처리 규칙**

- **연료는 회랑 쿼리에서 적용**한다 (`price_{fuel} > 0`). 후처리 아님
- **시설·브랜드·품질인증·셀프여부는 검색 결과를 받은 뒤 클라이언트에서 적용**한다. 필터를 바꿔도 재검색하지 않고 현재 목록만 다시 그린다. 셀프 필터를 위해 검색 결과에 `isSelf`를 함께 담는다
- **허용 우회 거리는 결과 화면의 별도 거리 설정 카드에서 바꾸는 STAGE 2 검색 파라미터**다 (§6.6). 카드를 누르면 바텀시트가 열리고, 적용 시 서버는 선택 거리+3km 범위의 후보를 조회하고 Valhalla 실제 `ΔD`가 선택 거리 이내인지 확인한다. 값을 바꾸면 재검색하며, 새 결과에도 현재 클라이언트 필터를 그대로 적용한다
- 시설 필터는 상세 API 백필이 진행 중이라 확인된 주유소만 통과한다 → 커버리지 안내 배너를 함께 노출한다 (§5.3)
- 필터 적용 후 후보가 0건이면 **활성 필터가 원인일 수 있음을 안내하고 초기화를 제안**한다
  - 예: _"선택하신 필터 조건에 맞는 주유소가 없습니다. [필터 초기화하고 목록 보기]"_

**출력**

```
{ facilities: ["CAR_WASH"|"MAINTENANCE"|"CVS"], brands: ["SKE","GSC",...], kpetroOnly: false, selfOnly: false }
```

**② 우회 고지 배너 — 제거 금지**

STAGE 2가 실행되어 🟡우회 후보가 최종 목록에 남으면, "경로 밖까지 살펴서 돌아가도 이득인
곳을 담았다"를 배너로 알립니다. 이 문장이 뜨는 순간이 이 제품의 존재 이유입니다.

**STAGE 1만으로 끝난 경우(경로상 후보만 표시) 배너는 뜨지 않습니다** — 아무것도 우회하지
않았으므로 고지할 것이 없습니다.

| 조건                                            | 문구                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------- |
| 최종 목록에 🟡우회 존재 (`expansion.triggered`) | `경로에서 {실제확장거리} 떨어진 곳까지 살펴, 우회 가능한 {주유소/충전소}도 함께 보여드려요.` |
| 🟡우회 없음 (STAGE 1만으로 종료 포함)           | **배너 없음**                                                                       |

| 변수             | 값                                                                          |
| ---------------- | --------------------------------------------------------------------------- |
| `{실제확장거리}` | 최종 목록에 남은 🟡우회 후보의 최대 `d_perp`를 km로 올림 (§7.2 STEP 10 7번) |

- **고정값 `15km`를 쓰지 마십시오.** `T3_MAX`는 탐색 상한이지 실제로 찾은 거리가 아닙니다.
  7km까지만 찾았는데 "15km까지 넓혀 찾았습니다"라고 하면 거짓입니다
- 배너는 **`result` 이벤트를 받은 뒤 확정 렌더링**합니다. `partial` 시점의 `finalRadiusM`은
  아직 후보가 걸러지기 전이라 달라질 수 있습니다

**③ 기준 모드 탭**

- 3개: `균형`(기본) / `최소비용` / `최단거리`
- 탭 전환 시 순위 재계산 (§8)
- **API 재호출 없이 즉시 반영되어야 함.** 이미 받아온 후보를 재정렬하는 것

**④ 결과 카드**

| 요소              | 표시 규칙                                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 순위 번호         | 현재 모드 기준 순위                                                                                                                                         |
| 티어 배지         | 🟢 경로상 / 🟡 우회 — **두 가지뿐** (§6.4). STAGE 1은 Valhalla 실제 `ΔT`·`ΔD`로 분류하고, STAGE 2는 우회로 표시하며, 상세에서 Kakao 경로로 최종 확인한다 |
| 주유소명 + 브랜드 | 브랜드는 §5.2 매핑표의 표시명                                                                                                                               |
| 리터당 가격       | 가격이 없으면 카드 자체를 목록에서 제외                                                                                                                     |
| 우회 거리·시간    | **표시하지 않음.** 검색 목록에는 `+N km`, `+N분`, `약 N km`, `약 N분`을 렌더링하지 않는다. 상세 화면에서만 실제 수치를 표시한다 |
| 순절감액          | 기존 가격·추천 이유 표시 규칙을 유지한다. 검색 후보는 Valhalla 실측을 계산에 사용하지만 Kakao 최종 확인 전이므로 확정 우회 수치로 표시하지 않는다 |
| 시설 배지         | 🚿 세차 / 🏪 편의점 / 🔧 경정비 — 있는 것만                                                                                                                 |
| 가격 기준일자     | `2026-09-04 기준` (유가 CSV 일 1회 스냅샷 기준일자). 별도 "오래된 정보" 경고는 넣지 않는다 — 날짜 자체가 정보다 (2026-09-05 결정)                           |

- **검색 결과 후보는 모두 추정 상태로 시작합니다** (`detour.precise === false`). 사용자가 상세에 진입하면 `/api/detour`가 실제 경유 경로를 계산해 상세 화면에서만 확정 수치를 표시합니다
- **손해인 후보도 숨기지 않고 회색으로 표시**한다. "여기 들르면 손해"를 아는 것도 가치

**⑤ 계산 전제 — 제거 금지**

- 반응형 배치. 모바일은 결과 목록 하단에 고정하고, 데스크톱은 왼쪽 사이드바의 `계산 기준` 영역에 표시한다. 내용은 `{기준가문구} {P_ref}원/L 대비 · 연비 {E}km/L · {Q}L 주유 기준 [수정]`이다.
- `{기준가문구}`는 `refPriceSource`에 따라 다릅니다

| `refPriceSource` | 문구             |
| ---------------- | ---------------- |
| `MEDIAN_T1T2`    | `경로 주변 평균` |
| `SIGUNGU_AVG`    | `지역 평균`      |

- **연비는 선택된 연료의 기본값을 씁니다** (§9.2). LPG 검색인데 휘발유 연비를 표시하면 안 됩니다
- 탭하면 시트가 열려 연비·주유량·시간가치 수정 가능. **수정 시 API 재호출 없이 즉시 재계산**
- 수정값은 `localStorage` 저장

**⑥ 허용 우회 거리 — 선택적 추가 탐색**

허용 우회 거리 설정 카드는 경로상 후보 유무와 무관하게 결과 화면에 항상 노출합니다. 경로상
후보가 있으면 기본값 `없음`에서 STAGE 1 목록만 표시합니다. 사용자가 3·5·10·15km를 선택하면
STAGE 1 측정값을 재사용하고 새 우회 후보만 추가 측정한 뒤, 경로상 후보와 중복 제거해 같은
목록에 합칩니다. 경로상 후보가 없으면 기존 동작대로 5km 우회를 자동 적용합니다. 탭은 경로를
바꾸는 기능이 아니라 합쳐진 목록 전체를 최단거리·최소비용·균형 기준으로 다시 정렬합니다.

**허용 우회 거리 설정 카드** (`components/result/max-detour-bar.tsx`) — **결과 화면의 필터 시트 밖**

- 카드에는 `허용 우회 거리 · 없음` 또는 `허용 우회 거리 · Nkm 이내`를 표시한다. 경로상 후보가 있으면 없음·3·5·10·15km, 없으면 3·5·10·15km 선택 바텀시트를 연다
- 경로상 후보가 있으면 기본값은 `없음`, 없으면 자동 5km. 현재 경로에서만 사용자 선택을 유지하며 새 경로에서는 다시 후보 유무에 따라 결정
- 서버는 선택 거리+`DETOUR_SEARCH_BUFFER_M`(3km)를 DB 검색 반경으로 사용하고, `T3_MAX`(15km)를 넘기지 않음
- 검색 결과에는 검색 반경 안의 후보를 먼저 Valhalla로 실측하고, 실제 `ΔD`가 선택 거리 이내인 후보만 남김
- 바텀시트에서 값을 바꾸고 `적용하고 다시 검색`을 누르면 page.tsx의 `detourIntent`를 세팅해 STAGE 2를 재검색합니다. 필터 시트의 다른 항목은 이 재검색을 일으키지 않고 현재 목록만 다시 그립니다 (§5.2)

**후보 0건일 때 — 빈 화면 금지**

```
┌──────────────────────────────────────────────┐
│  이 경로에서 조건에 맞는 주유소를 찾지 못했습니다 │
│  ({실제탐색거리}까지 탐색)                     │
│                                              │
│  [ 필터 초기화하고 목록 보기 ]                │  ← 활성 필터가 있을 때
│  [ 허용 우회 거리를 {N}km로 늘리기 ]           │  ← ⑥이 원인이고 다음 선택지가 있을 때만
│  [ 목적지 근처 주유소 보기 ]                   │
│  [ 출발지 근처 주유소 보기 ]                   │
└──────────────────────────────────────────────┘
```

`{N}`은 현재 선택 거리 밖에서 발견된 가장 가까운 실제 우회거리를 km로 올림한 값입니다.
화면의 버튼은 3·5·10·15km 선택지 중 다음 단계만 제시합니다.

`{실제탐색거리}`는 상황에 따라 다릅니다. **여기도 `15km`를 하드코딩하지 마십시오.**

STAGE 1은 `ON_ROUTE_PREFILTER_MAX_M`(300m)까지만 먼저 훑고, 경로상 후보가 없거나 사용자가
거리를 선택하면 STAGE 2에서 적용 거리+3km까지 넓힙니다. 따라서 화면의 탐색 반경은 적용값에
따라 달라지고, 최대 `T3_MAX`(15km)입니다.

### 5.4 F8 — 주유소 상세

**목적** 선택한 주유소의 전체 정보와 **왜 추천되었는지**를 보여주고, 내비로 연결한다.

**화면 구성**

```
┌──────────────────────────────────────────────┐
│ ← E1 홍천충전소                    🟡 우회    │
├──────────────────────────────────────────────┤
│  [ 지도: 기본 경로(회색) + 경유 경로(강조) ]   │
├──────────────────────────────────────────────┤
│  💡 추천 이유                                 │
│  12.4km 우회하지만 리터당 108원 저렴해         │
│  3,252원 이득입니다.                          │
│                                              │
│  · 가격     검색 후보 중 가장 저렴            │
│  · 우회     12.4km / 18분                    │
│  · 예상 순이득   +3,252원                    │
├──────────────────────────────────────────────┤
│  가격                                        │
│  LPG        1,102원/L    오늘 12:00 기준     │
│  45L 주유 시 예상  49,590원                   │
│  ⚠️ 가격은 실제와 다를 수 있습니다.            │
├──────────────────────────────────────────────┤
│  시설       🚿 세차  🏪 편의점                 │
│  브랜드     E1                                │
│  주소       강원 홍천군 ...                    │
│  전화       033-XXX-XXXX                    │
├──────────────────────────────────────────────┤
│  [ 카카오맵으로 길찾기 ]                      │
│  [ 네이버지도로 길찾기 ]                      │
│  [ TMAP으로 길찾기 ]                          │
│  [SearchAlert] TMAP 이용 시 경로는 주유소까지만  │
│  안내됩니다.                                    │
└──────────────────────────────────────────────┘
```

**추천 이유 생성 규칙 — AI를 쓰지 않습니다**

템플릿 규칙으로 생성합니다. 아래 조건을 위에서부터 검사해 **처음 맞는 것 하나**를 씁니다.

| #   | 조건           | 문구                                                                               |
| --- | -------------- | ---------------------------------------------------------------------------------- |
| 1   | 1위 & T3       | `{ΔD}km 우회하지만 리터당 {가격차}원 저렴해 {NetSaving}원 이득입니다.`             |
| 2   | 1위 & T1       | `경로에서 바로 진입할 수 있으면서 가격도 이 경로에서 {가격순위}번째로 저렴합니다.` |
| 3   | 최저가         | `이 경로에서 가장 저렴합니다. 다만 {ΔD}km 우회가 필요합니다.`                      |
| 4   | 최소 우회      | `경로에서 가장 가깝습니다. 우회 {ΔT}분.`                                           |
| 5   | 필터 조건 매칭 | `{조건}이 있는 곳 중 가장 {모드기준}입니다.`                                       |
| 6   | 그 외          | `가격과 우회 거리의 균형이 좋습니다.`                                              |

- `{가격차}` = `P_ref − P_s`
- `{ΔD}`는 소수 첫째 자리 km, `{ΔT}`는 분 단위 반올림
- **문구 아래에는 항상 지표 3줄을 함께 표시**합니다 (가격 순위 / 우회 / 예상 순이득). 문장만 있으면 근거를 알 수 없고, 숫자만 있으면 읽히지 않습니다

**가격 경고 문구 규칙 — 제거 금지**

| 조건          | 문구                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| 항상          | `가격은 실제와 다를 수 있습니다.`                                       |

**미계산 후보 진입 시**: `detour.precise === false`인 카드로 진입하면, 상세 화면 진입과 동시에 경유 경로를 1회 호출해 실측값으로 교체합니다. 교체 전에는 우회 정보를 `약 …` 표기로 유지합니다.

### 5.6 F10 — 내 주변 주유소

**목적** 경로와 무관하게 현재 위치 기준으로 가까운 주유소를 보여준다.

**규칙**

- 현재 위치 기준 반경 `SEARCH_RADIUS`(3km), 선택한 연료
- 기존 시설·브랜드·품질인증·셀프 필터를 제공한다. 허용 우회 거리는 제공하지 않는다
- 카카오맵에 현재 위치와 주변 주유소를 가격 마커로 표시
- 가격 마커를 탭하면 `가격 · 거리 · 시설 배지 · 기준시각`을 확인하고 상세 화면으로 진입
- 경로가 없으므로 추천 이유·우회 정보·지도의 경유 경로는 표시하지 않는다
- 주변 상세에서는 현재 위치와 선택한 주유소를 `내 위치 → 도착지`로 표시하고, 지도에 출발·도착 핀과 카카오 길찾기로 계산한 실제 도로 경로를 보여준다. 이 경로는 F10 정보 표시용이며 추천 순위에는 반영하지 않는다.
- 상세에서 카카오맵·네이버지도·티맵을 목적지 안내로 열 수 있다. 티맵은 주유소까지만 안내한다.
- 내비 연결은 주유소를 목적지로 전달

**이 기능의 위치**

차별점이 없는 기능입니다. 오피넷 앱이 이미 완벽하게 합니다. 그럼에도 넣는 이유는 셋입니다.

1. 경로 탐색은 장거리 이동 때만 쓰이므로 **평소에 열어볼 이유**가 필요하다
2. 경로 기능의 부품(주유소 조회·좌표변환·카드 UI)을 그대로 재사용하므로 추가 비용이 거의 없다
3. 후보 0건일 때의 폴백 화면으로 재활용된다

**→ 여기에 시간을 많이 쓰지 마십시오.** 기능이 커지면 제품의 초점이 흐려집니다.

## 6. Domain Rules

### 6.1 Route (경로)

| 개념            | 정의                                   |
| --------------- | -------------------------------------- |
| 기본 경로 `R₀ᵖ`  | 우선순위 p의 출발지 → 목적지 직행. 경유지 없음       |
| `D_baseᵖ` / `T_baseᵖ` | 기본 경로 p의 총 거리(m) / 총 소요시간(초)       |
| 폴리라인 `Pᵖ`    | 기본 경로 p를 구성하는 WGS84 좌표 배열             |
| 경유 경로 `R_sᵖ` | 기본 경로 p를 기준으로 주유소 s를 경유한 경로       |

**규칙**

- 카카오 `RECOMMEND`·`TIME`·`DISTANCE`를 기본 경로로 조회합니다. 폴리라인이 같은 응답은 우선순위가 높은 하나만 남겨 고유 경로 집합을 만듭니다
- 각 고유 기본 경로의 회랑 후보를 DB에서 모은 뒤, 기본 경로 폴리라인 전체를 Valhalla에 map-match하고 후보별 `출발지 → 주유소 → 목적지` 경로를 계산합니다. 같은 주유소가 여러 경로에 있으면 실제 총 소요시간 → 실제 총 거리 → 실제 `ΔT` → 실제 `ΔD` → 경로 우선순위 순으로 하나를 고릅니다
- 검색의 실제 `ΔT`·`ΔD`와 배지는 Valhalla로 계산하고, 사용자가 주유소 상세를 열면 `/api/detour`에서 Kakao 경로로 최종 확인합니다
- `D_baseᵖ < MIN_ROUTE_DISTANCE`(20km)이면 안내 후 진행 — 우회 이득이 거의 없는 구간
- 폴리라인 좌표는 **WGS84로 보관**하고, 거리 계산 시에만 미터 단위 투영좌표로 변환합니다
- 경로 API 응답의 `duration`은 실시간 교통 반영 여부가 확인되지 않았습니다. 확인 전까지 "예상 시간"으로만 표기합니다

### 6.2 RefuelPoint (주유소·충전소)

> 오피넷 원본 필드명(`UNI_ID`, `GIS_X_COOR` …)과의 매핑은 [`ARCHITECTURE.md`](ARCHITECTURE.md) §5.1이 소유합니다. **원본 필드명은 `infra/opinet/` 밖으로 새어나가면 안 됩니다** ([`../AGENTS.md`](../AGENTS.md) §7.3). 도메인은 아래 속성만 압니다.

| 속성          | 타입                            | 비고                                     |
| ------------- | ------------------------------- | ---------------------------------------- |
| `id`          | string                          | PK                                       |
| `name`        | string                          |                                          |
| `brand`       | string                          | 표시명 매핑은 §5.2                       |
| `lat` / `lng` | number                          | **WGS84.** 오피넷 KATEC 좌표를 변환한 값 |
| `address`     | string                          | 도로명 우선, 없으면 지번                 |
| `tel`         | string \| null                  | T3 추천 시 필수 노출                     |
| `sigunCd`     | string                          | `P_ref` 시군구 집계 키 (§6.3)            |
| `energyType`  | `OIL` \| `LPG` \| `BOTH`        | LPG 판정                                 |
| `facilities`  | `{ carWash, maintenance, cvs }` | 필터용 — 상세 API 백필로 채워짐          |
| `kpetro`      | boolean                         | 품질인증 — 상세 API 백필로 채워짐        |
| `isSelf`      | boolean \| undefined            | 셀프여부. undefined=미상                 |

**규칙**

- 주유소 마스터는 전부 **`refuel_point`에서 조회**합니다. 가격·상표·주소·셀프여부는 일 1회
  유가 CSV 임포트가, 시설·품질인증·전화는 백필 크론이 채웁니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §7.1)
- **영업 여부는 알 수 없습니다.** CSV에 7일 이상 등장하지 않은 곳(`last_seen_on`)은 회랑
  쿼리에서 제외하지만, 그 밖의 폐업은 탐지하지 않습니다

### 6.3 Price (가격)

| 개념             | 정의                                              |
| ---------------- | ------------------------------------------------- |
| `price`          | 리터당 판매가 (원, 정수)                          |
| `pricedOn`       | 가격 기준일자 — 유가 CSV 메타행에서 파싱한 날짜   |
| `P_ref`          | 기준가. "그냥 아무 데나 들렀을 때 냈을 법한 가격" |
| `refPriceSource` | `MEDIAN_T1T2` 또는 `SIGUNGU_AVG`                  |

**가격 갱신 주기**

가격은 **일 1회 유가 CSV 임포트**로 갱신됩니다(새벽). 오피넷 CSV 자체는 카드 단말기
연동분이 하루 6회(1·2·9·12·16시·19시) 반영되지만, 이 서비스가 받는 스냅샷은 하루 한 번입니다.

**실시간이 아닙니다. 항상 몇 시간~하루 지난 값입니다.** 화면에는 기준일자만 표시하고
(`"2026-09-04 기준"`), 별도 "오래된 정보" 경고는 달지 않습니다. 임포트가 실패하면 어제
데이터로 계속 서비스하며 배너로 기준일자를 알립니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §5.3.2).

**`P_ref` 산출 규칙 ★**

```
base = T1 ∪ T2   (검색 후보, 화면 표시 필터 적용 전)

if count(base) ≥ P_REF_MIN_BASE:        // 2
    P_ref = median(base.price)
    refPriceSource = "MEDIAN_T1T2"
else:
    P_ref = 시군구 가중평균 (아래)
    refPriceSource = "SIGUNGU_AVG"
```

**시군구 가중평균 산출**

1. 검색 후보 `pool`의 각 후보에서 `sigunCd`를 모은다 (화면 표시 필터 적용 전)
2. 시군구별 후보 수를 가중치로, 해당 시군구의 **선택 연료 평균가**를 가중평균한다
3. 시군구 평균가는 `refuel_point`에서 그때그때 집계한다 (`avg(price_{fuel})`) → **추가 API 호출 0회**
4. 시군구 평균가가 없으면 시도 평균 → 전국 평균 순으로 폴백
5. 전부 없으면 A14 (절감액 표시 생략)

**왜 이렇게 하는가**

- **중앙값을 쓰는 이유:** 평균은 이상치(비정상 저가·고가) 하나에 크게 흔들립니다. 중앙값은 안정적입니다
- **T1+T2를 기준으로 하는 이유:** 사용자가 도구 없이 그냥 운전했다면 눈에 보이는 경로 근처 주유소에 들렀을 것이기 때문입니다. 실제 대안 집합이 기준이어야 "절약"이 정직해집니다
- **T1+T2가 2개 미만일 때 시군구 평균으로 바꾸는 이유:** 후보가 1개면 "중앙값"이 그 한 곳의 가격 자체가 되어 기준이 아니라 우연이 됩니다. 0개면 `pool`(=전부 T3) 중앙값이 되는데, 그러면 "3,252원 이득"이 *경로 주변 대비 절감*이 아니라 *멀리 있는 것들끼리의 상대값*이 됩니다. LPG 저밀도 구간이 정확히 1순위 타깃 시나리오인데, 거기서 핵심 숫자의 의미가 무너집니다

> ⚠️ **화면에 기준을 항상 밝히십시오.** §5.3 ⑤의 문구 규칙을 따릅니다. 기준을 숨긴 절감액은 과장 광고입니다.

### 6.4 탐색 티어 — 제품의 뼈대

주유소를 검색 단계에서 **두 등급**으로 나눕니다. `d_perp`는 먼저 경로상 후보와 우회 후보를
나누는 검색 단계 기준으로 사용하고, STAGE 1 경로상 후보의 배지는 Valhalla가 계산한 실제
`ΔT`·`ΔD`로 결정합니다. STAGE 2에서 범위를 넓혀 찾은 후보는 실제 `ΔT`·`ΔD`가 작더라도
우회 후보로 표시합니다. 상세 진입 후에는 `/api/detour`의 Kakao 경로로 최종 확인합니다.

| 배지      | 검색 단계 조건                                                                 | 의미                             |
| --------- | ----------------------------------------------------------------------------- | -------------------------------- |
| 🟢 경로상 | **STAGE 1** 후보 중 실제 `ΔT ≤ ON_ROUTE_MAX_S` **그리고** `ΔD ≤ ON_ROUTE_MAX_D` | 가는 길에 들를 가능성이 높은 후보 |
| 🟡 우회   | **STAGE 2**에서 찾았고 실제 `ΔD ≤ maxDetourDistanceKm` 및 내부 안전 cap을 통과한 후보, 또는 STAGE 1에서 경로상 기준을 넘은 후보 | 실제로 갈 수 있는 우회 후보. `NetSaving > 0`이면 추천, 그 밖은 참고 |

**검색 단계에서 폴리라인 전체를 map-match하는 이유 ★**

`d_perp`(경로 폴리라인까지의 직선거리)만으로는 중앙분리대·유턴·IC 진입 비용을 구분할 수 없습니다.
따라서 Kakao의 기본 폴리라인 전체를 Valhalla에 map-match해 실제 도로망 기준의 기본 경로를 만들고,
주유소를 경유한 경로와 비교합니다. 이때 `ΔT`·`ΔD`를 함께 봐야 재라우팅으로 시간만 0이거나
거리는 짧아지는 예외를 놓치지 않습니다.

상세 화면에서는 주유소 경유 경로를 실제로 조회해 `ΔT`·`ΔD`를 표시합니다. 다음 사례처럼
`d_perp`는 후보 수집과 기준가 표본을 위한 보조 값이고, 실제 우회 수치의 확정 수단이 아닙니다:

| 사례                               | `d_perp` | 상세 `ΔT` | 상세 `ΔD`  | 의미                         |
| ---------------------------------- | -------- | --------- | --------- | ---------------------------- |
| 경로 117m 옆인데 U턴 두 번         | 117m     | 7분       | 300m      | 검색 방향 필터만으로 확정하지 않음 |
| 재라우팅으로 시간만 0, 4.5km 더 돎 | 4.5km    | 0분       | 4.5km     | 상세에서 실제 우회량을 확인       |
| 진짜 가는 길에 있는 곳             | 600m     | 1분       | 800m      | 검색 경로상 후보의 상세 확인       |

**`d_perp`의 용도는 세 가지로 분리합니다**

1. **`P_ref` 표본 정의** — `d_perp ≤ T2_MAX`(3km) 후보의 가격 (§6.5). "이 지역 시세"는 기하 개념이 맞습니다
2. **STAGE 1 사전 범위** — `d_perp ≤ ON_ROUTE_PREFILTER_MAX_M`(300m) 후보만 먼저 Valhalla로 측정합니다
3. **STAGE 2 회랑 범위 필터** — 선택 거리+3km로 DB를 조회하되 `T3_MAX`를 넘기지 않습니다. 회랑 안 후보는 실제 경로를 계산합니다

`ON_ROUTE_PREFILTER_MAX_M`·`T2`·`T3`라는 이름은 위 용도의 **내부 개념으로만** 남고 화면에 나오지 않습니다.

**검색에서도 실제 경로를 계산합니다.** 검색 결과의 정렬·우회 거리 판정은 Valhalla의 실제 경로를
사용합니다. STAGE 1의 배지만 Valhalla 실제 `ΔT`·`ΔD`로 경로상 여부를 확정하고, STAGE 2는
우회로 표시합니다. `detour.precise`는 Kakao 상세 확인 전까지 `false`로 유지하며,
상세 화면은 `/api/detour` 응답의 Kakao 실제 폴리라인·`ΔT`·`ΔD`를 최종 표시합니다.

**우회 후보의 이동 가능성과 추천 가치를 분리하는 이유**

거리만으로 추천하지는 않지만, 실제로 갈 수 있는 후보까지 `NetSaving ≤ 0`이라는 이유로 삭제하지도 않습니다. 사용자가 5km·10km를 선택했는데 결과가 몇 곳뿐이면 검색을 제대로 못 한 것처럼 느낄 수 있기 때문입니다.

따라서 STAGE 2에서 실제 `ΔD`가 선택 거리 이내이고 내부 안전 cap을 통과한 후보는 목록 후보로
보존합니다. 절감 없음·손해 후보도 삭제하지 않으며, 경로상 후보와 함께 **현재 모드 점수로
전체 정렬**합니다. 선택 거리 조건은 **우회 탐색(STAGE 2)에만** 적용됩니다.
경로상 후보는 STAGE 1에서만 Valhalla의 실제 `ΔT`·`ΔD`로 확정하며, Kakao의 최종 우회 비용은
상세에서 확인합니다.

**검색 반경과 실제 우회거리를 분리합니다 ★**

사용자가 5km를 선택하면 DB는 `5km + 3km = 8km` 회랑까지 조회합니다. 이 여유 범위는
직선거리와 실제 도로거리의 차이로 후보가 빠지는 것을 줄이기 위한 것입니다. 하지만 8km 안에서
찾았다는 이유만으로 추천하지 않습니다. Valhalla가 계산한 실제 `ΔD`가 5km 이내인 후보만 다음
단계로 통과시킵니다. 15km 선택 시에는 18km가 아니라 `T3_MAX`인 15km까지만 조회합니다.

**`T3_MAX` 상한은 반드시 적용합니다.** STAGE 2의 회랑 bbox가 넓게 잡히므로 경로 끝단이나 급커브
구간에서 `d_perp > 15km`인 후보가 섞여 들어올 수 있습니다. 티어 분류 단계에서 즉시 제거하십시오.

**경로상(🟢) 후보에는 `NetSaving` 게이트를 적용하지 않습니다.** 어차피 돌아가지 않는 곳이라 "이득인가"를 따질 이유가 없고, 사용자가 "여긴 비싸구나"를 확인하는 것 자체가 정보입니다. 게이트는 **우회 후보에만** 겁니다.

### 6.5 Route × RefuelPoint — 이 제품의 핵심

**검색 결과에서 경로상으로 분류하는 주유소란 무엇인가**
→ STAGE 1(`d_perp ≤ ON_ROUTE_PREFILTER_MAX_M`) 후보 중 map-match된 기본 경로와 주유소
경유 경로를 비교해 `ΔT(s,p) ≤ ON_ROUTE_MAX_S`(180초) 그리고
`ΔD(s,p) ≤ ON_ROUTE_MAX_D`(1.5km)를 모두 만족하는 주유소입니다.
STAGE 2에서 범위를 넓혀 찾은 후보는 두 값이 기준 이내여도 `우회`로 표시합니다.
`d_perp`는 `P_ref` 표본과 STAGE 1·STAGE 2 후보 수집 범위를 결정하는 데 사용합니다.

**`d_perp` 계산 규칙**

- 점과 폴리라인의 **각 선분**에 대한 최단거리의 최솟값입니다. **폴리라인 꼭짓점까지의 거리가 아닙니다**
- **미터 단위 투영좌표에서** 계산합니다. 위경도(도 단위)로 하면 위도에 따라 왜곡됩니다

**얼마나 떨어진 주유소까지 후보로 보는가**
→ STAGE 1은 `d_perp ≤ ON_ROUTE_PREFILTER_MAX_M`(300m), STAGE 2는 `d_perp ≤
min(maxDetourDistanceKm + DETOUR_SEARCH_BUFFER_M, T3_MAX)`입니다. 단, STAGE 2 최종 후보는
Valhalla 실제 `ΔD ≤ maxDetourDistanceKm`이고 내부 안전 cap을 통과해야 합니다. 기준가가 있으면
경로상·우회 후보를 현재 모드 점수로 함께 정렬합니다. 기준가가 없으면 A14에 따라 절감액을
숨기고 가격순으로 정렬합니다.

**우회 거리·시간은 어떻게 계산하는가**

| 방식             | 식                                                                                                                                  | 언제                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| DB 사전 검색     | `d_perp ≤ maxDetourDistanceKm + 3km`, 단 최대 `T3_MAX`                                                                             | STAGE 2 후보 확보                 |
| **검색 실측**    | Valhalla `R_sᵖ`와 map-match 기본 경로 비교<br>`ΔD(s,p) = max(0, R_sᵖ.distance − D_baseᵖ)`<br>`ΔT(s,p) = max(0, R_sᵖ.duration − T_baseᵖ)` | 검색 후보 전체                    |
| **최종 실측**    | Kakao `R_sᵖ`와 Kakao 기본 경로 비교                                                                                               | 주유소 상세 진입 시 `/api/detour` 1회 |

**직선거리와 실제 도로거리를 섞지 않습니다.** `d_perp`는 DB에서 후보를 모으는 공간 기준이고,
추천 목록에 들어갈지는 Valhalla의 실제 `ΔD`·`ΔT`로 결정합니다. 중앙분리대·유턴·IC 진입 비용을
직선거리 계수로 추정하지 않기 때문에, 직선거리상 가까워도 실제 우회가 큰 후보는 제외할 수 있습니다.

**정밀 계산이 이 서비스 신뢰도의 전부입니다.** 검색 결과는 Valhalla 실측값으로 티어·정렬·예산을 계산하지만,
Kakao 최종 확인 전이므로 `detour.precise=false`를 유지하고 확정 수치처럼 표시하지 않습니다. 상세 진입 후
Kakao 실측값을 `+N km · +N분`으로 표시합니다.

> 검색 결과는 Valhalla 실측을 사용하지만 `detour.precise=false`입니다. Kakao 최종 확인 전에는 확정 수치처럼 표시하지 않습니다.

**`ΔD`만으로는 우회를 표현할 수 없습니다 ★** (Phase 10 실측 — `verify:detour`)

경유지를 넣으면 카카오가 경로를 **재탐색**합니다. 고속도로 대신 국도를 타면 거리는 같거나 짧은데 시간만 늘어납니다. 40.4km 경로에서 추정 상위 40곳을 실측한 결과:

| 지표                         | 값                                                |
| ---------------------------- | ------------------------------------------------- |
| `ΔD = 0`                     | **60%** (거리로는 "우회 없음")                    |
| `ΔT` 중앙값                  | **7.9분** (p25 4.2 / p75 9.5 / 최대 39.1)         |
| `d_perp` 0~200m 구간 `ΔT`    | 중앙값 **8.2분** (현행 추정 `ΔT̂` 0.2분 — 40배 차) |
| `d_perp` 500~1000m 구간 `ΔT` | 중앙값 **4.8분**                                  |

**`d_perp`가 작을수록 `ΔT`가 오히려 컸습니다.** 경로에 붙어 있는 주유소일수록 간선도로·고속도로 옆이라 진입·복귀가 비싸기 때문입니다. 즉 우회 비용의 지배항은 이탈 거리가 아니라 **진입·복귀 고정비**이고, 그것은 `d_perp`로 예측되지 않습니다.

그래서 **실질 우회 거리**를 정의합니다 — `ΔD`와 `ΔT` 중 나쁜 쪽을 거리 단위로 통일한 값:

```
ΔD_eff(s) = max( ΔD(s),  ΔT(s) / 3600 × AVG_SPEED × 1000 )     [m]
```

`ΔT`를 `AVG_SPEED`로 거리 환산하므로 **새 임계값을 표본 부족 상태로 추정할 필요가 없습니다.** 쓰이는 곳은 `Score_minDistance` 하나입니다 (§8).

> **`ΔD_eff`를 배지 판정에 쓰지 마십시오.** `ΔD_eff`는 상세 실측값에서 계산하는 최단거리 모드 점수 전용 파생값입니다.
>
>
> 검색 결과의 배지·배너·정렬은 Valhalla 실제 `ΔT`·`ΔD`에서 결정하고, 상세 화면의 `ΔT`·`ΔD` 표시는 `/api/detour` Kakao 실측값에서 최종 확인합니다. 검색 결과는 Kakao 확인 전이므로 `precise:false`입니다.

**음수 클램프가 필요한 이유:** 경유지를 넣으면 경로가 재탐색되어 기본 경로보다 짧거나 빨라지는 경우가 실제로 있습니다. 그대로 두면 "-3분 우회"가 표시됩니다.

**주유 비용과 순절감액**

```
NetSaving(s) = 절감액 − 우회연료비
             = (P_ref − P_s) × Q − (ΔD(s)/1000 / E) × P_s

TotalCost(s) = 주유비 + 우회연료비
             = Q × P_s + (ΔD(s)/1000 / E) × P_s

  P_ref : 기준가 (§6.3)                   [원/L]
  P_s   : 주유소 s의 리터당 가격            [원/L]
  Q     : 주유량 (기본 45)                 [L]
  ΔD    : 우회 추가 거리                   [m]  ← 함수 인자는 m
  E     : 연비 (기본 LPG 8.5)              [km/L]
  결과  : 원 (정수로 반올림)
```

> **단위에 주의하십시오.** `ΔD`는 **미터**로 전달되고 `E`는 **km/L**입니다. `/1000`을 빠뜨리면 우회 연료비가 1,000배가 되어 모든 후보가 탈락합니다. 함수 시그니처 규약은 [`../AGENTS.md`](../AGENTS.md) §7.4를 따르십시오.

> **`NetSaving`에 시간 비용을 넣지 않습니다.** 시간은 `ΔT`로 화면에 별도 표시하고, 시간을 돈으로 볼지는 사용자가 판단합니다. 균형 모드의 정렬에서만 내부적으로 환산합니다 (§8).

**최저가와 최적 주유소를 어떻게 구분하는가**
→ 최저가는 `min(P_s)`, 최적은 현재 기준 모드의 점수가 가장 낮은 후보입니다. 둘은 다를 수 있고, 다를 때 추천 이유 템플릿 #3이 그 차이를 설명합니다.

**여러 경로가 있을 경우** → 카카오 `RECOMMEND`·`TIME`·`DISTANCE`를 비교합니다. 같은 폴리라인은
한 번만 탐색하고, 같은 주유소는 실제 경유 뒤 도착 시간·거리 기준으로 더 좋은 경로 버전 하나만
남깁니다. 목록 탭은 이 경로 선택과 독립적으로 정렬만 바꿉니다.

---

### 6.6 선택적 우회 — 2단계 탐색

**규칙.** 먼저 `RECOMMEND`·`TIME`·`DISTANCE` 기본 경로를 받고 같은 폴리라인을 합칩니다.
STAGE 1에서는 각 고유 기본 경로의 `d_perp ≤ ON_ROUTE_PREFILTER_MAX_M` 후보만 모은 뒤 기본
폴리라인 전체를 Valhalla에 map-match하고, 후보별 경유 경로를 실제로 계산합니다. 경로상 후보가
있으면 우회 거리 기본값은 `없음`이며 STAGE 1 목록만 반환합니다. 경로상 후보가 0곳이면 기존
기본값 5km로 STAGE 2를 자동 실행합니다. 사용자가 거리를 선택한 경우에는 경로상 후보 유무와
무관하게 선택 거리+3km 회랑(최대 `T3_MAX`)까지 범위를 넓혀 우회 후보를 추가합니다. STAGE 2
후보는 실제 `ΔT`·`ΔD`가 작아도 화면에서는 우회로 유지합니다.

```
STAGE 1 — 경로상 목록 (항상 실행)
  각 고유 기본 경로의 d_perp ≤ ON_ROUTE_PREFILTER_MAX_M(300m) 후보를 조회한다.
  기본 폴리라인 전체를 map-match하고 후보별 Valhalla 경유 경로를 계산한다.
  ΔT ≤ ON_ROUTE_MAX_S(180초) AND ΔD ≤ ON_ROUTE_MAX_D(1.5km)인 후보를 합친다.
  같은 주유소는 실제 총 시간·거리·우회량·경로 우선순위 순으로 하나만 남긴다.
  경로상 후보가 있으면 우회 거리=없음 → 이 목록만 반환한다.
  경로상 후보가 0곳이면 우회 거리=5km를 자동 적용해 STAGE 2로 간다.

STAGE 2 — 우회 탐색 (경로상 0곳 또는 사용자가 3·5·10·15km를 선택했을 때)
  각 고유 기본 경로의 d_perp ≤ min(선택 거리+3km, T3_MAX) 후보를 새로 조회한다.
  STAGE 1에서 이미 잰 후보는 재사용하고, 새 후보에만 Valhalla 경유 경로를 계산한다.
  모든 후보의 Valhalla 실제 `ΔT`·`ΔD`를 계산한다.
  실제 `ΔD ≤ 선택 거리`, 내부 안전 cap을 통과한 후보만 남긴다.
  STAGE 2 후보는 모두 🟡우회로 표시한다.
  STAGE 1 경로상 주유소와 중복되면 경로상 버전 하나만 남긴다.
  경로상·우회 후보를 현재 모드 점수로 함께 정렬한다.
  검색 결과의 수치는 Kakao 최종 확인 전이므로 `detour.precise=false`로 담는다.
```

**왜 STAGE 1을 먼저 보는가.** 경로상 후보가 있으면 최초 화면에서 가는 길의 후보만 빠르게
보여주고, 없으면 기존 기본값 5km로 자동 확장하기 위해서입니다. 사용자가 거리를 선택했을 때도
STAGE 1 결과를 버리지 않고 재사용해야 새 후보만 추가 측정할 수 있습니다. 중앙분리대·유턴·IC
진입 비용은 폴리라인 거리만으로 추측하지 않고 Valhalla 경로로 확인합니다.

**누락 방지.** STAGE 1은 300m 사전 범위에서 빠르게 경로상 여부를 확인하고, 경로상 후보가
없거나 사용자가 거리를 선택하면 T3 회랑까지 DB 범위를 넓힙니다. STAGE 2에서 찾은 후보는
Valhalla가 실제 `ΔT`·`ΔD`를 계산하더라도 화면에서는 우회 후보로 유지합니다. 그래야 범위를
넓혀 찾은 후보가 경로상 후보로 오표시되지 않습니다. 실제 우회 경로를 계산하지 못한 후보는
결과에서 제외하고 경고를 남깁니다.

**허용 우회 거리는 STAGE 2에서만 검색 입력으로 작동합니다.** 경로상 후보가 있는 상태에서
`없음`이면 STAGE 2를 실행하지 않습니다. 경로상 후보가 없으면 기본 5km, 거리 선택 시에는
후보 유무와 무관하게 선택값으로 우회 후보를 추가합니다.

**허용 우회 거리는 표시 필터가 아니라 검색 입력입니다 ★**

이 값은 **DB 검색 반경과 실제 후보 판정**을 바꾸므로, 이미 받은 목록을 클라이언트에서 잘라내는 방식으로는 성립하지 않습니다.

```
서버: "5km까지" 전제로 8km 회랑 후보를 조회하고 실제 경로를 계산
      → 실제 ΔD가 5km 이내인 후보만 남김
사용자: 필터를 10km로 넓힘
화면: 서버가 13km 회랑을 새로 조회하고 실제 ΔD가 10km 이내인 후보를 다시 계산
```

값이 바뀌면 **재검색**해야 합니다. 검색은 Valhalla 후보 경로를 실제로 계산하므로 서버에서 새 거리로 다시 평가해야 합니다.

경로상 후보가 있으면 선택지는 없음·3·5·10·15km이고 기본값은 없음입니다. 경로상 후보가
없으면 선택지는 3·5·10·15km이고 기본값은 5km입니다. DB 검색 여유는 3km이며, 전체 회랑은
15km를 넘지 않습니다.

**폐기 — `T1_PRIORITY_GAP_WON`(100원/L).** 초기 시도에서 "T1이 있으면 T2·T3는 100원/L 이상 싸야 노출"이라는 예외 조항을 뒀지만, `ΔT` 기준으로 경로상을 정의하는 순간 **예외가 정의 안으로 흡수됩니다** — "2분 우회에 150원 싼 곳"은 예외로 살릴 필요 없이 애초에 경로상 후보이기 때문입니다. 게다가 100원 flat은 연료를 가리지 않아, 지역 내 가격 폭이 좁은 **LPG에서는 사실상 "우회 후보 전멸"** 로 작동했습니다(실측: 남한산성입구역→단대오거리역 LPG 결과 1건). 이 파라미터는 삭제합니다.

## 7. 추천 알고리즘

### 7.1 전체 파이프라인

```
STEP 1  기본 경로 탐색 — RECOMMEND·TIME·DISTANCE, 동일 폴리라인 제거 [경로 API 최대 3회]
STEP 2  회랑 수집 — 고유 경로별 폴리라인 bbox로 refuel_point 조회       [외부 호출 0]
STEP 3  검색 후보 준비 — 연료 조건 적용. 화면 표시 필터는 응답 후 클라이언트에서 적용
STEP 4  d_perp 산출 · 선택 거리+3km(최대 T3_MAX) 회랑 밖 제거
STEP 5  기준가 P_ref 산출
STEP 6  기본 폴리라인 전체 map-match + 후보별 Valhalla 경유 경로 실측
        실제 ΔT ≤ ON_ROUTE_MAX_S AND ΔD ≤ ON_ROUTE_MAX_D 후보를 합침
        경로상 후보가 있으면 우회 거리=없음에서 전부 반환

STAGE 2 — 우회 탐색 (경로상 0곳 또는 사용자가 거리를 선택했을 때)
STEP 7  적용 거리+3km(최대 15km) 회랑 후보를 조회하고 Valhalla로 전부 실측
STEP 8  실제 ΔD ≤ 선택 거리 + 내부 안전 cap 적용, STAGE 1과 중복 제거
STEP 9  경로상·우회 후보를 현재 모드 점수로 전체 정렬

STEP 10 결과 확정 + 추천 이유 생성

※ 검색 결과는 Valhalla 실측을 사용하지만 `detour.precise=false`입니다. 사용자가 상세에
   진입하면 `/api/detour`에서 Kakao 경로로 1회 최종 확인합니다.
```

> **STEP 번호는 2단계 탐색 재설계에서 재배열했습니다.** 파이프라인이 2단계로 갈라지면서 옛
> 번호(구 STEP 7·8·8.5·9·10·11)를 그대로 두면 실행 순서와 번호가 어긋나기 때문입니다.
> 대응: 구 7 → 신 5, 구 8 → 신 7, 구 9 → 신 8, 구 10 → 신 9, 구 11 → 신 10.
> 구 STEP 5·6("확장 수집")과 구 STEP 8.5(T1 우선순위 필터)는 **삭제**됐습니다 —
> 전자는 회랑 bbox 쿼리로, 후자는 §6.6의 2단계 구조로 대체됐습니다.

### 7.2 STEP 상세

**STEP 1 — 기본 경로**

```
routes = routeAPI(origin, destination, priority ∈ {RECOMMEND, TIME, DISTANCE})
→ 같은 폴리라인은 우선순위가 높은 하나만 남겨 고유 기본 경로 R₀ᵖ 집합 구성
→ 각 경로 p의 D_baseᵖ (m), T_baseᵖ (초), polyline Pᵖ
```

실패 시 1회 재시도, 그래도 실패하면 전체 중단.

**STEP 2 — STAGE 1 경로상 사전 수집**

```
corridor = bbox(project(P)) 를 ON_ROUTE_PREFILTER_MAX_M(300m) 만큼 넓힌 사각형
pool = SELECT * FROM refuel_point
        WHERE lat/lng BETWEEN corridor
          AND price_{fuel} > 0                 // A3 — 미취급 제외
          AND last_seen_on >= today - 7일       // 폐업 추정 제외
```

폴리라인 전체의 bbox를 한 번에 조회하므로 경로 곡률·샘플 간격 같은 개념이 없습니다.
사각형이 실제 회랑보다 넓게 잡히는 만큼은 STEP 4의 `d_perp` 필터가 걸러냅니다.
경로상 후보가 없거나 사용자가 우회 거리를 선택했을 때 같은 방식으로 적용 거리+3km 회랑을
다시 조회합니다. 경로상 0곳에서 명시 선택이 없으면 적용 거리는 5km입니다. 전체 검색 반경은
`T3_MAX`(15km)를 넘지 않습니다.

`P_ref` 표본은 별도 조회로 `T2_MAX`(3km)까지 확보합니다. 이 조회는 기준가 계산 전용이며
후보별 Valhalla 경로 측정을 시작하지 않습니다.

**STEP 3 — 검색 후보와 화면 표시 필터 분리**

| 필터                      | 적용 방법                                                                                                         |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 연료 종류                 | STEP 2 쿼리에서 `price_{fuel} > 0`으로 적용                                                                       |
| 브랜드                    | 검색 결과의 `WireCandidate.brand`를 클라이언트에서 매칭                                                        |
| 시설 (세차·경정비·편의점) | 검색 결과의 `facilities`를 클라이언트에서 매칭. 미확인은 `false`라 자동 제외                                |
| 품질인증                  | 검색 결과의 `kpetro`를 클라이언트에서 매칭                                                                    |
| 셀프                      | 검색 결과의 `isSelf = true`만 클라이언트에서 매칭. 미상(`NULL`)은 제외                                         |

이 필터들은 이미 받은 후보를 대상으로 하므로 **추가 호출이 없고, 조건을 바꿔도 재검색하지 않습니다.**
허용 우회 거리만 DB 검색 범위와 Valhalla 판정을 바꾸므로 별도 컨트롤에서 바꿀 때 재검색합니다.

**STEP 4 — `d_perp` 산출 · 범위 밖 제거**

```
for each station s in pool:
    d_perp(s) = 점-폴리라인 최단거리(s, P)          // 투영좌표에서
    if d_perp > T3_MAX → 제거 ★

STAGE 1 후보군 = { s | d_perp(s) ≤ ON_ROUTE_PREFILTER_MAX_M }
STAGE 2 후보군 = { s | d_perp(s) ≤ T3_MAX }                  // 경로상 0곳 또는 거리 선택 시
```

여기서 **티어를 만들지 않습니다.** `T1_MAX`는 더 이상 쓰이지 않고, `T2_MAX`는 `P_ref` 표본 정의에만 남습니다 (§6.4).

**STEP 5 — 기준가 `P_ref`** → §6.3

**STEP 6 — 경로상 목록 ★ 핵심 판정 (STAGE 1)** → §6.6

```
후보 = { s | d_perp(s) ≤ ON_ROUTE_PREFILTER_MAX_M }
기본 경로 = Valhalla.trace_route(map_snap, Pᵖ)
경유 경로 = Valhalla.route(origin, s, destination)
ΔD(s,p) = max(0, 경유 경로 거리 - map-match 기본 경로 거리)
ΔT(s,p) = max(0, 경유 경로 시간 - map-match 기본 경로 시간)
onRoute = { s in 후보 | ΔT(s,p) ≤ ON_ROUTE_MAX_S AND ΔD(s,p) ≤ ON_ROUTE_MAX_D }
if onRoute ≠ ∅ AND maxDetourDistanceKm가 선택되지 않음:
    return onRoute 전체
else:
    적용 거리 = maxDetourDistanceKm ?? DEFAULT_MAX_DETOUR_DISTANCE_KM(5km)
    → 적용 거리+3km 회랑을 조회해 STAGE 2 후보를 추가한다.
```

**가격순 상한을 두지 않는 이유.** STAGE 1 경로상 후보는 가격이 아니라 실제 `ΔT`·`ΔD`로 결정합니다. 같은 주유소가 여러 기본 경로에 있으면 실제 총 경로 시간·거리·우회량과 경로 우선순위로 하나만 남깁니다.

**검색 정밀 계산의 범위.** 검색은 Valhalla로 후보 전체를 측정합니다. 응답의 `precise`는 Kakao 최종 확인 전이라 `false`이고, 실제 Kakao 경유 경로는 상세 화면에서 선택한 주유소 1곳에 대해서만 계산합니다.

**STEP 7 — STAGE 2 후보 실측 ★**

```
    detourPool = 선택 거리+3km 회랑 후보              // 최대 T3_MAX, 거리 선택 시에만

for each s in detourPool:
    Valhalla로 실제 경유 경로를 계산한다.
    ΔD(s) = max(0, 경유 경로 거리 - map-match 기본 경로 거리)
    ΔT(s) = max(0, 경유 경로 시간 - map-match 기본 경로 시간)
    if ΔD(s) > maxDetourDistanceKm × 1000 → 제거
    if 내부 안전 cap 초과 → 제거
    if P_ref가 있으면 netSaving(s, ΔD, P_ref, vehicle) 계산
    STAGE 1 경로상 주유소와 중복되면 우회 버전 제거
```

사용자 거리 조건은 추정치가 아니라 Valhalla 실측 `ΔD`에만 적용합니다. `ΔT`는 화면의 사용자 필터가
아니며, 중앙분리대·유턴처럼 시간만 크게 늘어나는 경로를 막는 내부 안전 cap에 사용합니다.

**STEP 8 — 1차 스코어링**

3개 모드 각각의 점수를 **Valhalla 실측 `ΔD`, `ΔT` 기준**으로 계산합니다 (§8).

**STEP 9 — 전체 후보 정렬 (STAGE 2)**

STAGE 2에서는 새 후보를 🟡우회로 표시하고, Valhalla 실측 우회거리·시간으로 거리 조건과 내부
안전 cap을 적용합니다. 이후 기존 경로상 후보와 합쳐 현재 모드 점수로 전체 정렬합니다. 티어는
정렬 우선순위가 아니라 배지·배너에만 사용합니다. 검색 후보의
`detour.precise`는 Kakao 최종 확인 전이라 `false`이고, 사용자가 상세에 들어간 후보만 `/api/detour`에서
최종 확인합니다.

**STEP 10 — 최종 정렬 + 추천 이유**

```
0. 최종 후보 = STEP 6 경로상 목록 + STEP 9 실제 우회 목록 (우회 미선택 시 경로상만)
1. Valhalla 실측 `ΔD`·`ΔT`로 NetSaving·점수 계산
2. STAGE 1 경로상 후보는 실제 `ΔT`·`ΔD` 두 기준으로, STAGE 2 우회 후보는 실제 `ΔD`·안전 cap 결과로 이동 가능 여부 결정
3. 경로상·우회 후보 전체를 현재 모드 점수로 정렬. 기준가가 없으면 가격순
4. 경로상 후보는 전부 보존하고 우회 후보에만 MAX_RESULTS(15) 적용
5. 추천 이유 템플릿 적용 (§5.4)
6. expansion.finalRadiusM = 최종 목록의 🟡우회 후보 중 최대 d_perp — 기하 도달 거리 (없으면 0)
   expansion.triggered = STAGE 2 최종 목록에 🟡우회 후보가 1곳 이상 존재
```

> `partial`과 `result`의 후보는 Valhalla 검색 실측값을 사용하지만 `precise:false`입니다. 상세 화면에서
> `/api/detour`가 Kakao 최종 경로·`ΔD`·`ΔT`·순이득을 반환하면 그 화면의 수치만 최종 실측값으로 교체합니다.

**검색과 상세를 분리하는 이유 ★**

검색 목록은 Valhalla 후보별 경유 경로를 제한된 동시성으로 계산해 중앙분리대·유턴·IC 진입 비용을 반영합니다.
최종 Kakao 경로를 검색 결과 정렬에 섞으면 후보 수만큼 유료 쿼터가 발생하므로, Kakao 최종 확인은 상세로 미룹니다.

`partial`과 `result`는 같은 추정 후보 집합을 전달합니다. 사용자가 상세에서 실측을 요청하면 상세 화면의 수치만 갱신하고
검색 결과 목록을 다시 정밀 계산하지 않습니다.

### 7.3 왜 2단계로 나누는가 (추정 → 정밀)

검색 단계의 후보 누락 방지와 중앙분리대·유턴 반영을 위해 Valhalla 경유 경로를 검색에서도 계산합니다.
Kakao 경유 경로는 최종 확인이 필요한 상세 주유소 1곳에만 호출합니다.

| 방식            | 검색·상세 경로 API 호출                   |
| --------------- | ----------------------------------------- |
| 검색            | 기본 경로 최대 3회 + Valhalla map-match·후보별 경유 호출 |
| 주유소 상세 1건 | 기본 경로 캐시 재사용 + Kakao 경유 경로 최대 1회      |

경로 캐시가 Kakao 기본 경로 재호출을 흡수하며, Valhalla 검색 경로는 제한된 동시성과 타임아웃을 적용합니다.
검색 결과의 우회 거리·시간은 Kakao 최종 확인 전이므로 `precise:false` 표시 규칙을 따릅니다.

## 8. 기준 모드 3종

세 모드 모두 **같은 계열의 목적함수**이고, 항이 하나씩 늘어나는 구조입니다. 전부 **최소화** 문제입니다.

### 최단거리

```
Score_minDistance(s) = ΔD_eff(s) = max( ΔD(s), ΔT(s) / 3600 × AVG_SPEED × 1000 )   [m]
```

우회만 본다. 가격 무시. _"돌아가기 싫다"_

**`ΔD`가 아니라 실질 우회 거리(§6.5)를 쓰는 이유:** 실측 후보의 **60%가 `ΔD = 0`** 입니다(경유지를 넣으면 경로가 재탐색되어 거리는 그대로인데 시간만 늘어남). `ΔD`만 보면 그 60%가 전부 0점 동점이 되어 "최단거리" 정렬 자체가 무의미해집니다.

### 최소비용

```
Score_minCost(s) = TotalCost(s)
                 = Q × P_s  +  (ΔD(s)/1000 / E) × P_s      [원]
                   └주유비┘    └──── 우회 연료비 ────┘
```

주유비와 우회로 더 태우는 기름값의 합. 시간 무시. _"돈만 아끼면 된다"_

### 균형 (기본값)

```
Score_balanced(s) = TotalCost(s) + (ΔT(s)/60) × V_TIME     [원]
                                   └── 시간 비용 ──┘
```

시간을 돈으로 환산해서 더한다. `V_TIME` 기본 200원/분 (시급 12,000원 기준).

> **단위:** `ΔD`는 m, `ΔT`는 초로 전달됩니다. `E`가 km/L이고 `V_TIME`이 원/분이므로 함수 내부에서 각각 `/1000`, `/60` 변환이 필요합니다. [`../AGENTS.md`](../AGENTS.md) §7.4.

### 설계 메모

- **전부 원(₩) 단위라 자연스럽게 합쳐집니다.** 정규화나 임의 가중치가 필요 없습니다. 이 설계의 가장 큰 장점입니다
  - 예외: `minDistance`만 m 단위입니다. 다른 두 모드와 점수를 비교하지 마십시오. 모드 내 정렬에만 씁니다
- **실측값이 함께 있는 컨텍스트에서 정렬의 1차 키는 모드 점수가 아니라 `detour.precise`입니다** (§7.2 STEP 10). 검색 결과는 Valhalla 실측을 사용하지만 Kakao 최종 확인 전이라 `precise:false`이고, 상세 화면의 Kakao 실측값은 검색 목록 정렬에 다시 섞지 않습니다
- **가중치 슬라이더를 두지 않습니다.** "가격 0.7 / 시간 0.3"이 무슨 뜻인지 사용자는 모릅니다. **탭 3개로 사용자가 의도를 표현하게** 합니다
- 화면에 표시하는 `NetSaving`은 모드와 무관하게 **항상 시간 미포함 금액**입니다. 우회 시간은 별도로 항상 표시됩니다. 판단은 사용자 몫입니다

### 10.3 로딩 표시

탐색 단계가 길어질 수 있으므로 **단계별 진행 상황**을 실제 서버 진행에 맞춰 보여줍니다. (SSE `progress` 이벤트 — [`ARCHITECTURE.md`](ARCHITECTURE.md) §6.2)

```
가장 빠른 길을 찾고 있어요       ●○○○     progress: ROUTE
근처 주유소를 살펴보고 있어요     ●●○○     progress: COLLECT
경로 주변을 더 넓게 찾아보고 있어요 ●●●○     progress: EXPAND   ← 경로상 0곳 또는 우회 거리 선택 시
곧 결과를 보여드릴게요           ●●●●     progress: PRECISE
```

> **`EXPAND` 단계는 경로상 후보가 0곳이거나 사용자가 우회 거리를 선택해 STAGE 2에 진입할 때 방출됩니다.** 최종 우회 후보가
> 게이트에서 모두 탈락하더라도 T3 회랑까지 실제로 살폈으므로 범위 확장 단계는 유효합니다.
> 로딩에서는 탐색 상한 `T3_MAX`를 거리처럼 노출하지 않고 범위 확장 사실만 알립니다. 실제 거리는
> 결과 배너에서 채택된 우회 후보의 최대 `d_perp`로만 보여줍니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §6.2).

> 이 문구들은 **가짜 애니메이션이 아닙니다.** 서버가 실제 단계를 스트리밍으로 알려줍니다.

> 성공 결과를 수신하면 클라이언트가 마지막 **결과 준비** 표시와 경로 끝점 도착을 마친 뒤
> 결과 화면으로 전환합니다. 준비 이벤트가 생략되거나 여러 이벤트가 한꺼번에 도착해도
> 이 마지막 표시를 보장합니다. 실제로 거치지 않은 `EXPAND`는 완료 체크 대신 건너뜀으로
> 표시하며, 이를 위해 서버에 별도의 스킵 이벤트를 추가하지 않습니다.

> **JSON 폴백이 걸린 경우에만 예외입니다.** 진행 상태를 알 수 없으므로 `EXPAND` 문구는
> 절대 보여주지 않고, 나머지 문구만 시간 기반으로 순서대로 표시한 뒤 마지막 문구에서 기다립니다 — 최종 후보에 T3가 있는지
> 모르는 상태에서 "넓게 찾는 중"을 띄우면 이 제품이 가장 경계하는 "근거 없는 표시"가 됩니다.

## 11. 성공 지표와 로깅

### 11.1 지표 3개

| 지표                              | 왜 이것인가                                                      |
| --------------------------------- | ---------------------------------------------------------------- |
| **T3 발동률**                     | T1·T2로 충분해서 T3가 거의 안 뜬다면, 차별 기능이 사실상 없는 것 |
| **T3 발동 검색의 내비 연결률**    | 우리가 찾아준 "우회할 가치 있는 곳"을 사용자가 실제로 채택했는가 |
| **T1·T2만 뜬 검색의 내비 연결률** | 위 지표의 비교군. 두 값이 같으면 T3 탐색은 헛수고였다는 뜻       |

### 11.2 로깅 정책

이 지표를 측정하려면 서버 이벤트 기록이 필요합니다. **개인 식별 가능 정보는 저장하지 않습니다.**

| 딥링크 클릭: 앱·순위·티어·순절감액               |                               |

원본 기획의 _"서버에 사용자 데이터를 저장하지 않는다"_ 는 **"개인 식별 가능 데이터를 저장하지 않는다"** 로 해석합니다. 익명 집계 이벤트는 저장합니다. 이 지표 없이는 T3 탐색이 가치가 있는지 검증할 수단이 없습니다.
